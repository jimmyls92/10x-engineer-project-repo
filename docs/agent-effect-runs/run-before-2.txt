I've added `GET /collections/{collection_id}/prompts` and five tests for it. The full suite passes: **24 passed, 0 failed**. The warnings are the ones that were already there (Pydantic `Config`, `utcnow()`, httpx). Nothing was committed, and `CLAUDE.md` and the prompt log are unchanged.

**The endpoint** (`backend/app/api.py`, just after `get_collection`):
- It returns a `PromptList` (`{"prompts": [...], "total": n}`), sorted newest first like `GET /prompts`.
- **An unknown collection gives 404 `"Collection not found"`.** This is a deliberate difference from `GET /prompts?collection_id=<id>`, which returns an empty list for an unknown id. With the new endpoint, an empty list always means the collection exists and has no prompts.
- It reuses `storage.get_prompts_by_collection` and `sort_prompts_by_date`, so there is no new storage code.
- I also changed the `get_collection` docstring to point to the new endpoint instead of the query-string filter.

**Tests** (new `TestCollectionPrompts` class in `backend/tests/test_api.py`):

| Test | Checks |
|---|---|
| `test_lists_only_prompts_in_collection` | Prompts in another collection or in none are left out |
